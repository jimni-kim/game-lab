# 새 루프 설계 (G5)

작성: 2026-11-14. 상태: **구현함(`src/gamelab/agent.py`). 재실측은 [G5 보고](../reports/2026-11-14-g5-agent-loop.md).** 구현하며 달라진 점은 맨 아래 "구현하며 정한 것". 근거와 통과 기준은 [PLAN §10](../PLAN.md)의 "새 루프를 새로 쓰는 근거와 통과 기준".

## 무엇을 바꾸나

지금 한 판은 루프 세 개가 나눠 돈다.

| 지금 | 하는 일 | 새 루프에서 |
|---|---|---|
| `adaptation._begin`, `identify` | 게임을 알아봄 | 그대로 부름(첫 단계) |
| `Adaptation.explore` | 모델이 읽고 풀이기가 고르는 첫 6수 | L2의 한 구간. 6수에서 끝나지 않음 |
| `GameSession` + `ScreenEnvironment` | 어댑터가 읽고 풀이기가 고름. 의도 저장, 영수증, 사람 승인, 덮개 판정 | L3. 새로 씀. ARMY 장치 없음 |
| `play_adaptive`의 바깥 루프 | 막히면 다시 배우기 | 루프 안의 "한 화면을 L2로 읽기" |
| `Recovery` | 판이 없을 때 모델의 입력 | L0. 그대로 부름 |

새 모듈은 `src/gamelab/agent.py` 하나다. `session.py`, `environments/screen.py`, `play.py`는 고치지 않고 기준선 경로(등록 프로필, `eval web --profile`)만 쓴다.

## 한 턴

```text
보기      화면이 가라앉기를 기다려 캡처
읽기      L3: 생성 어댑터(measure, read)   L2: 모델(label_screen) → 규칙 모델 validate
          판이 없으면 → L0(복구 한 번) 뒤 다시 보기
끝 판정   규칙 모델 status. 목표 도달, 게임 끝
고르기    풀이기(이 판에서 효과 없던 수는 뺌)
입력      L3: 어댑터 target   L2: 모델이 준 판 상자로 계산한 키·탭
확인      다시 보고 읽어 규칙 모델 assess: 확인 / 없음 / 불일치
기록      수, 단계, 효과, 시간. L2로 읽은 화면은 어댑터 생성의 look이 됨
오르내림  아래 표
```

- 읽는 쪽과 고르는 쪽은 갈아 끼우는 값이다. 루프 본문은 하나다.
- **L2로 읽은 화면은 모두 look이다.** 탐색과 다시 배우기가 따로 없다. look이 `EXPLORE_MOVES`만큼 쌓이면 어댑터를 만들고, 채택되면 L3으로 간다.

## 오르내림

| 언제 | 무엇을 | 상수 |
|---|---|---|
| L2에서 확인된 look이 6개 | 어댑터 생성 → 채택되면 L3. 이후 3수는 시험 수(하나라도 어긋나면 L2로) | `EXPLORE_MOVES` 6, `TRIAL_MOVES` 3 |
| L3에서 못 읽음, 불일치, 효과 없음이 연속 | 그 화면을 L2로 읽어 look에 더하고 채택 시험. 통과 못 하면 다시 생성 | 지금의 다시 배우기와 같음 |
| 어댑터 생성 실패, 또는 한 판에서 다시 생성이 한도를 넘음 | **L2로 그 판을 이어 감.** 수가 확인된 look이 `RETRY_LOOKS`만큼 더 쌓이면 한 번 더 생성 | `MAX_GENERATIONS` 5, `MAX_RELEARNS` 16, `RETRY_LOOKS` 12, 판당 재시도 2 |
| 어느 단계든 판이 없음 | L0: 복구 입력 하나. 연속 6번까지 | `recovery.MAX_TRIES` |
| L2에서 모델의 읽기가 규칙에 안 맞음 | 다시 묻기 2번, 그래도 안 되면 L0 | `LABEL_RETRIES` |
| 예산(시간, 수, 모델 토큰)이 다함 | 끝 | 판당 입력 30만 토큰, 15분(기본값) |

- 규칙 없는 게임을 모델이 직접 두는 것(L0에서 수 두기, L1)은 이 단계에 넣지 않는다. 식별되지 않으면 지금처럼 `game_not_identified`로 끝난다. 루프의 "고르기"를 갈아 끼우는 자리만 둔다.

## 결과

| 결과 | 뜻 |
|---|---|
| `goal_reached` | 목표에 닿음 |
| `game_over` | 게임이 끝남(짐, 더 둘 수 없음) |
| `budget_exhausted` | 수, 시간, 토큰 가운데 하나가 다함(이유에 적음) |
| `gave_up` | 모델이 더 할 수 있는 것이 없다고 답했거나 복구 한도에 닿음. 모델이 말한 상황을 이유로 남김 |
| `unsupported` | 게임을 알아보지 못함, 입력 종류가 없음 |

`needs_recovery`(사람이 이어받음)와 `user_stopped`는 없다. 취소는 `budget_exhausted / cancelled`로 적는다.

## 옮겨 올 동작 (코드가 아니라 시험으로)

| 동작 | 지금 어디 | 새 루프에서 |
|---|---|---|
| 화면이 가라앉을 때까지 기다림, 멈추지 않는 판은 상태가 같으면 가라앉은 것으로 봄 | `session._settle`, `RESTLESS_S` | 어댑터의 `settling` 값을 그대로 씀 |
| 효과 없는 수는 그 판에서 다시 고르지 않음 | `record["ineffective"]` | 같음 |
| 화면 크기가 바뀌면 다시 잼 | `screen.remeasure` | `measure`를 매 턴 부름(생성 코드는 1초 안에 끝남) |
| 끝 화면이 판을 가려도 끝으로 판정 | `family.ended`, 장면 판정 질문 | 규칙 모델 `ended` + L2 읽기의 `scene` |
| 측정 훅(수마다 정답키와 대조) | `Watch` | 같은 훅을 받되 영수증 타입 없이 부름. `measure.Recorder`에 얇은 어댑터를 둠 |

버리는 것: 입력 전 의도 저장, 영수증과 재전송 판정, 입력 직전 재관측, lease, `cleanup_pending`, 사람 승인(`allow_meta`), 덮개 판정 질문(`classify_screen`. 복구 질문 하나로 합침), 한 번에 한 수 제한.

## 통과 기준

1. `tests/test_adaptation.py`, `test_adaptation_mines.py`, `test_recovery.py`, `test_identify.py`가 새 루프로 통과한다. 기존 세션의 기록 모양에 묶인 단언은 새 기록 모양으로 고친다.
2. 새 시험: 어댑터 생성이 실패해도 L2로 판이 끝까지 간다. 토큰 예산이 다하면 그 이유로 끝난다. 시험 수가 어긋나면 L2로 내려온다.
3. 2048 사이트 재실측 1판과 지뢰찾기 중급 1판: 수당 시간과 오독이 지금 수준(0.65초, 0.79초, 오독 0)이다.

## 구현하며 정한 것

- **스위치:** `eval web --generate`의 기본이 새 루프(`agent.play`)다. 기존 세션 경로는 `baseline.py`로 옮겼고 `eval web --loop session`으로 돈다(G6).
- **모델이 읽은 화면의 보증:** 수가 확인된 화면만 look으로 남긴다. 아무 수도 보증하지 않은 읽기(첫 화면, 복구 뒤의 화면)는 거기서 둔 수가 확인되지 않으면 버린다.
- **어댑터를 의심할 때:** 못 읽은 칸이 있으면 그 화면 하나를 모델이 읽고 바로 대조한다. 다 읽었는데 수가 어긋나면(시험 수 1번, 그 뒤 연속 3번) 모델이 읽으며 한 수를 확인한 다음 대조한다. 대조를 통과하면 어댑터로 돌아가고, 못 하면 다시 쓴다.
- **판이 안 보일 때:** 모델이 "판 없음"이라고 읽으면 다시 묻지 않고 바로 복구 질문으로 간다(질문 2번).
- **끝 화면:** 복구 질문의 답에 `end`(won, lost)를 더했다. 이긴 화면이 목표 도달인지는 규칙 모델이 정한다.
- **토큰 예산:** `Budget.max_input_tokens`(평가 명령 기본 30만). 모델에게 묻기 전에만 본다. 어댑터가 읽는 동안은 토큰이 다해도 판이 이어진다.
- **끝난 판의 어댑터:** 어댑터를 써 보기 전에 판이 끝났어도 화면이 충분하면 그때 써서 다음 판을 위해 보관한다.
- **안 한 것:** 15분 기본값은 평가 명령에 넣지 않았다(2048 한 판이 약 15분이라 G11에서 정함).
