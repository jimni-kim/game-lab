# G9 클론다이크 실측 (격자가 아닌 판)

작성: 2026-11-14. 모델 `gpt-6.1-sol`. 사이트는 `khang-nd.github.io/js-solitaire`(MIT 공개 소스, 페이지 요소로 그림). 계열을 주지 않고 시작했다(`eval web --site khang_solitaire --generate --identify`). 목표는 끝까지 두기이고, 한도는 입력 250개, 30분, 입력 60만 토큰이다.

| 판 | 결과 | 수 (확인 / 결과 못 읽음 / 없음 / 맞지 않음) | 모델이 읽은 수 / 어댑터가 읽은 수 | 시간 | 입력 토큰 | 어댑터 |
|---|---|---|---|---|---|---|
| 1 | `budget_exhausted / time` | 19 (14 / 5 / 0 / 0) | 19 / 0 | 1,823초 | 13.1만 | 5번 생성, 모두 504로 끝남 |

출력 3.2만 토큰, 모델 질문 47번. 복구 입력은 없었다.

## 본 것

- 식별: 질문 한 번에 클론다이크로 답했다.
- 확인된 14수는 더미 사이나 기반 더미로 옮긴 카드 11수와 덱 넘기기 3수다. 규칙 모델은 예측할 수 있는 카드를 모두 엄격하게 맞춰 보고, 수가 뒤집어 드러내는 카드만 열어 둔다. 그래서 이 확인은 매치3의 확인보다 강하다.
- 어댑터는 한 번도 써지지 않았다. 생성 5번이 모두 모델 게이트웨이의 `504 Gateway Time-out`으로 끝났고, 여기에 1,800초 중 약 950초를 썼다(386초의 8수와 1,339초의 9수 사이).
- 모델이 읽는 수는 수당 약 20~60초다. 모델이 상태와 함께 모든 자리(덱, 버린 더미, 기반 더미 4개, 일곱 더미의 앞면 카드 하나하나)의 상자를 답하기 때문이다.
- 사이트 없이: 풀이기(`greedy`)는 한 장 넘기기 모의 판 200개 중 75개(37.5%)를 이기고, 기준선(`first`)은 0개다. 가짜 화면 시험은 탐색, 어댑터 채택, 127수 만의 승리까지 가고, 모든 입력이 풀이기가 고른 자리 사이에 들어간다.

G9에서 만든 것(커밋 246e379): 규칙 모델 `rules/klondike.py`와 풀이기 `solvers/klondike.py`. 계열 descriptor가 게임의 자리를 이름 붙이고 모델이 자리마다 상자를 답한다(`places`). 입력은 자리 하나를 누르기와 자리 사이의 끌기다. 격자 덧그림, 칸별 색, 줄 훑기는 격자 계열에서만 쓴다. 채택 시험은 입력의 양 끝이 기록된 자리 안에 있는지 본다. 확인된 자기 수로 같은 상태에 세 번 돌아온 판은 `game_over / no_progress`로 끝난다. 공유 고정 사례 34개, 가짜 화면 시험 4개, 전체 시험 703개 통과.

## 한계와 남은 것

- 한 판이고, 끝내지 못했다. 한 판을 끝내려면 100수가 넘게 필요해서, 어댑터 없이는 시간 한도 안에 끝낼 수 없다.
- 생성된 코드가 실제 사이트에서 카드의 숫자와 무늬를 읽을 수 있는지는 시험되지 않았다. 채택 시험까지 간 생성이 없었다.
- 정답키는 읽지 않았다.
- 게이트웨이 시간 초과는 모델 답을 스트림으로 읽는 방식으로 따로 다루고 있다.

## 이어서: 보관된 화면으로 어댑터 생성 (사이트 없이)

모델의 답을 스트림으로 읽게 바꾼 뒤, 위 판에서 보관된 화면 8개로 생성만 다시 했다(모델 질문만, 사이트는 건드리지 않음).

- 504는 없었다. 생성 5번이 563초에 끝났다(입력 11.7만 토큰).
- 5번 모두 채택 시험에서 떨어졌다. 네 번은 읽은 상태를 규칙이 받지 않았고, 한 번은 뒤집힌 카드를 앞면 카드로 세고 그 값을 못 읽었다.
- 생성 코드가 카드의 숫자와 무늬를 처음부터 읽어 내지 못한다. 격자 게임의 칸은 색 몇 개로 갈렸지만, 카드는 작은 글자와 무늬 52가지를 갈라야 한다.

다음에 할 것: 어디에 무엇이 있는지(자리와 상자)는 생성 코드가 정하고, 그 자리에 있는 것이 무엇인지는 모델이 읽어 준 화면에서 잘라 둔 견본과 견줘 정하게 나눈다. 처음 보는 카드는 견본만 더하면 되고 코드를 다시 쓰지 않는다.
