## 3. 종류별 규칙

장르에서 흔한 형태를 적었다. 게임마다 세부는 다르다. "에이전트로 보면"은 이 하네스에서 계열로 만들 수 있는지를 본 것이다.

### 잼: 막힌 것을 순서대로 빼내기

판 위의 탈것이나 블록이 서로 길을 막는다. 어느 것을 먼저 빼야 길이 열리는지 순서를 찾는 퍼즐이다.

- **버스 잼** (Bus Fever, Bus Go, Super Dispatcher, Bus Crowd)
  - 색 승객이 대기 줄에 순서대로 서 있고, 정류장 칸 수가 정해져 있다.
  - 주차장의 버스를 누르면 앞이 비었을 때 정류장 빈칸으로 간다. 맨 앞 승객과 색이 같은 버스에 타고, 차면 떠난다.
  - 정류장이 찼는데 맨 앞 승객의 버스가 없으면 진다.
- **주차·차 잼** (Car Jam Solver, Parking Loop, Color Puzzle Jam)
  - 차마다 머리 방향이 있고, 누르면 그쪽으로 나간다.
  - 앞이 막히면 부딪혀 멈추거나 돌아온다. 목숨이 줄기도 한다.
  - 다 빼면 깬다.
- **블록 빼내기** (Color Block Jam, Block Out!, Sand Blocks)
  - 격자 위 색 블록을 끌어 가장자리의 같은 색 문으로 뺀다.
  - 다른 블록에 막히거나 문보다 크면 못 나간다. 제한 시간이 흔하다.
  - Sand Blocks는 모래가 물리로 흐르는 변형이다.
- **탭 탈출** (Farm Tap, Piggy Escape): 누르면 정해진 방향으로 빠진다. 화살표 빼내기와 같은 구조다.

> 에이전트로 보면: 주차·블록 빼내기는 격자 + 수 한 종류(누르기 또는 끌기)라서 만든 계열에 맞다. 버스 잼은 대기 줄과 정류장까지 상태에 들어가고, 줄 뒤쪽이 가려진다. 블록 빼내기는 제한 시간 때문에 수당 속도가 중요하다.

### 화살표 빼내기

Amaze GO, Arrows, Arrow Puzzle, MOVLO가 이 종류이고, 3D는 CubeAway, Cube Topia다.

- 누른 화살표는 그 방향으로 날아가 판 밖으로 나간다. 길에 다른 것이 있으면 부딪혀 실수 횟수가 준다.
- 모두 빼면 깬다. 길이 열린 것부터 빼야 한다.
- 화살표가 꺾인 선(뱀)인 게임도 있다. 3D판은 큐브를 돌리며 뺀다.

> 에이전트로 보면: 2D판은 격자 + 칸 누르기라서 계열에 가장 잘 맞는 종류다. 규칙은 "이 방향으로 빈 길이 있나" 하나다. 3D는 돌리기가 들어가 어렵다.

### 정렬

- **물·구슬·색** (Water Sort, Magic Sort, Marble Sort, Sort Streak)
  - 병을 하나 누르고 다른 병을 누르면, 맨 위의 같은 색 층들이 옮겨 간다.
  - 받는 병이 비었거나 맨 위 색이 같고 자리가 남을 때만 된다.
  - 모든 병이 한 색으로 차면 깬다. 막히면 빈 병 추가나 되돌리기 아이템을 쓴다.
- **실·로프** (Rope Sort, Yarn Loop, Wool Crush): 실타래나 로프를 같은 색 자리로 옮긴다. 같은 규칙에 그림만 다르다.
- **음식·물건·방** (Skewer Jam, Pocha Moonlight, Amochiroom, Tidy Room)
  - 선반이나 꼬치에서 같은 물건 3개(N개)를 한 칸에 모으면 사라진다.
  - 방 정리는 물건을 제자리에 넣는 쪽에 가깝다.
- **동전 정렬 머지** (Pocket Sort): 같은 값을 모으고, N개가 되면 다음 값이 된다.
- **나사** (Screw Out 3D, Unscrew Frenzy 3D)
  - 판자가 나사로 겹쳐 고정돼 있다. 나사를 누르면 같은 색 상자로 간다.
  - 나사가 다 빠진 판자는 떨어진다.
  - 맞는 상자가 없으면 임시 칸에 두고, 임시 칸이 차면 진다.

> 에이전트로 보면: 물 정렬은 판이 격자가 아니라 "병 N개 × 층 K개" 더미다(클론다이크와 같은 자리형). 규칙이 아주 단순하고, 판독은 병마다 층 색만 읽으면 된다.

### 머지

Gossip Harbor, Tasty Travels, Flambé, Mystery Town, Pines Peak가 이 종류다.

- 격자 판(대략 7×9)에서 같은 물건 2개를 끌어 겹치면 한 단계 위 물건이 된다.
- 생성기를 누르면 에너지를 쓰고 낮은 단계 물건이 나온다.
- 손님 주문을 채우면 코인·별을 받고, 그것으로 스토리나 꾸미기가 진행된다.
- 에너지는 시간이 지나야 찬다. 한 번에 오래 두는 게임이 아니라 자주 들어와 조금씩 하는 게임이다.
- 수박 게임류(Watermelon Maker 2048)는 물리로 합쳐지는 다른 종류다.

> 에이전트로 보면: 판은 격자이고 수도 하나지만, 이기는 조건이 판이 아니라 주문·에너지에 있다. 작업·루틴 쪽이 맞다.

### 마작·타일 짝 맞추기

- **마작 솔리테어** (Vita Mahjong, Mahjong Blast)
  - 층으로 쌓인 타일 가운데 "자유" 타일만 고를 수 있다. 위가 덮이지 않고, 왼쪽이나 오른쪽 한쪽이 빈 타일이다.
  - 같은 무늬 2장을 고르면 없어지고, 모두 없애면 깬다. 짝이 없으면 막힌다(섞기 아이템).
- **트리플 타일** (Tile Club, Tap Tile!, Goods Triple Match 3D)
  - 맨 위 타일을 누르면 받침(보통 7칸)으로 내려가고, 같은 것 3개가 모이면 없어진다.
  - 받침이 다 차면 진다.

> 에이전트로 보면: 판이 겹친 더미라서 "덮였나, 자유인가"를 읽어야 한다. 마작은 웹에서 직접 두기로 둔 적이 있다(STATUS §2, S2: 같은 예산으로 입력 47 → 110).

### 5.2 사용자 제안과 검토

**사용자 제안:** 세부 카테고리마다 계열을 만들면 계열 수만 늘고 특정 게임 전용이 될 수 있다. 종류별 공통 규칙만 넣어 두고(프롬프트로?) L1·L2로 진행하면 어떤가.

**검토 결과: 방향(세부마다 계열을 만들지 않음)에는 동의한다.** 다만 수단을 고쳐야 한다.

- **규칙을 프롬프트로만 두면 L0이다.** L1과 L2는 규칙 모델이 코드로 있어야 성립한다.
  - L2: 규칙 모델이 모델이 읽은 판을 검사하고, 풀이기에 합법 수를 주고, 결과를 확인한다.
  - L1: 규칙 모델이 모델에게 고를 합법 수 목록을 준다.
  - 프롬프트뿐이면 직접 두기에 종류 메모를 붙인 것과 같다.
- **이미 있는 방식: 공통 규칙 코드 + 변형은 값(`rule_parameters`).**
  - 3매치 하나가 꿈의 집과 로얄 매치를 덮는다. 색 수, 힘 조각 방식, 장애물, 아래층, 레벨 목표가 값이다.
  - 모델은 첫 화면에서 보이는 값만 읽는다(`adaptation._rules`). 알 수 없는 값은 `null`로 두고 수의 결과로 배운다(`agent._learn_ways`).
  - 떨어지는 블록도 조각 종류·미리보기·층 목표가 값이라, 처음 보는 Pentris를 코드 변경 없이 두었다(PLAN §34 F6).

| 길 | 규칙 | 층 | 장점 | 단점 |
|---|---|---|---|---|
| A. 프롬프트에 종류 메모 | 글 | L0 | 거의 공짜 | 확인 없음, 판독이 늘 모델 |
| **B. 종류 계열 (권장)** | 사람이 쓴 코드 + 변형 값 | L2 → L3 | 규칙이 검사, 풀이기가 둠, 판독을 코드로 넘길 수 있음 | 종류마다 규칙·풀이기·기술자를 씀 |
| C. 만든 계열 + 종류 틀 | 모델이 틀에 맞춰 씀 | L2 | 사람 손이 적음 | Singles처럼 규칙이 안 서면 막힘(STATUS §3) |

- **L1보다 L2.** 이 종류들은 결정적이고 판이 다 보이는 퍼즐이라 풀이기가 싸다. 빼내기는 길이 빈 것부터 빼는 탐색, 정렬은 상태 해시를 쓴 깊이 우선 탐색이면 된다. L1은 수마다 모델 질문이 들어 비용이 직접 두기와 비슷하다. 풀이기를 믿기 어려울 때는 3매치의 "상위 6수 가운데 모델이 고르기"(`agent._pick`)가 L1 역할을 이미 한다.
- **A는 B와 따로 쓸 수 있다.** 계열이 없는 직접 두기 게임(약 80개)에 싸게 붙이는 용도다. 넣을 자리는 두 곳이다.
  - `play_direct.md`의 `[when …]` 꼬리표 줄: 식별 답에 종류(장르)를 하나 더 받아야 꼬리표를 켤 수 있다.
  - 직접 두기 문맥의 `memory` 첫 값: 모델이 덮어쓸 수 있다.

### 5.3 종류별 판단

**① 빼내기 (잼 + 화살표): 추천, 첫 번째**
- **공통 규칙:** 격자 위 조각마다 갈 수 있는 방향이 있다. 수 하나는 조각 하나를 고르는 것이다(누르기 또는 축을 따라 끌기). 막힐 때까지 가고, 출구까지 길이 비면 빠진다. 다 빼면 깬다.
- **변형 값:**
  - 방향: 화살표 고정 / 축 양쪽 / 아무 쪽
  - 출구: 아무 가장자리 / 같은 색 문 / 문 너비
  - 조각 모양: 1칸 / 꺾인 선(뱀) / 폴리오미노
  - 부딪힘: 안 움직임 / 되돌아오고 목숨 잃음
  - 목숨 수, 제한 시간
- **덮는 게임(약 12):**
  - 화살표 5: 33, 37, 90, 115, 136
  - 주차 3: 88, 104, 134
  - 탭 탈출 2: 129, 147
  - 블록 빼내기 2: 145, 180
- **뺄 것:**
  - 버스 잼: 대기 줄·정류장, 가려진 줄. 나중에 `dock` 값으로 될지 따로 본다.
  - Sand Blocks: 물리
  - 3D 큐브
- **위험:**
  - 누르면 빠지는 종류는 순서가 거의 자유라 풀이기가 할 일이 적고, 판독이 전부다. L2(3~7초)로는 직접 두기보다 나은 점이 작을 수 있다. 이득은 L3에서 나온다.
  - Color Block Jam류의 제한 시간

**② 정렬: 추천, 두 번째**
- **공통 규칙:** 그릇이 N개 있고 각각 칸 K개짜리 더미다. 수 하나는 "이 그릇에서 저 그릇으로"다. 맨 위의 같은 것 묶음이 옮겨 가고, 받는 쪽이 비었거나 맨 위가 같고 자리가 있을 때만 된다. 모든 그릇이 한 종류로 차거나 비면 깬다.
- **변형 값:**
  - 그릇 칸 수
  - 옮기는 단위: 맨 위 묶음 전체 / 한 개
  - 가려진 층 `?`
  - N개가 같으면 사라짐(물건·꼬치 정렬)
  - 빈 그릇 추가 아이템: `boosters`로
- **덮는 게임(약 8~10):** 17, 23, 43, 143, 189, 54, 91, 194, 실 정렬 일부(규칙 확인 필요)
- **뺄 것:** 나사(3D 판자), 동전 머지, 방 정리
- **확인할 것:** 조작이 "고르고 놓기"(누르고 또 누르기)다. 식별이 시험하는 조작 종류(`adaptation.EXPLORED_WITH`: keys, tap, drag, places)에 맞는지, 새 종류가 필요한지 코드에서 본다.

**③ 타일 짝 맞추기: 보류, 세 번째 후보**
- **공통 규칙:** 자유 타일만 고를 수 있다. 짝이 맞으면 사라지거나(마작) 받침으로 가서 N개가 모이면 사라진다(트리플). 받침이 차면 진다.
- **변형 값:** 짝 수 2/3, 받침 칸 수(없음/7), 자유의 정의
- **덮는 게임:** 5개(77, 86, 92, 132, 140)
- **어려운 점:** 가려진 타일이 있어 판이 다 보이지 않고, 겹친 더미 판독이 어렵다. 규칙도 보이는 자유 타일과 받침만 상태로 두는 약한 확인이 된다. ①②의 결과를 보고 정한다.

**④ 머지: 계열로 만들지 않음**
- 이기는 조건이 판 밖(주문, 에너지, 스토리)에 있고, 에너지가 시간으로 찬다.
- 작업·루틴·세계 기억으로 맡긴다. 예: "주문 3개 채워줘", "에너지 다 쓰기"
- 필요하면 길 A(종류 메모)만 붙인다.

### 5.4 판독 걱정: 생김새가 게임마다 다르다

**사용자 우려:** 이 종류들은 게임 수가 많고 생김새(버스, 실 등)가 매우 다르다. 하나의 판독기로 구분할 수 있나.

**검토 결과: 생김새가 다양한 것 자체는 큰 문제가 아니다. 판독을 막는 것은 판의 배치(기하)다.**

- **규칙 모델은 추상 상태만 본다.** "그릇 1: [색A, 색A, 색B]"를 볼 뿐, 물인지 실인지는 모른다.
- **격자 키트는 생김새를 사이트마다 배운다.** 공통 부품(`kits/grid.py`, `samples.py`)은 계열·게임·색을 모르고 다음을 한다.
  1. 판을 칸으로 나눈다.
  2. 생김새가 비슷한 칸끼리 묶는다.
  3. 첫 화면에서 모델이 묶음마다 이름을 붙이고, 그 견본을 사이트마다 보관한다.
- **선례:**
  - 3매치 키트가 꿈의 집(과일·꽃)과 로얄 매치(보석·왕관)를 같은 코드로 읽는다.
  - 2048 사이트 다섯 곳이 첫 7화면 안에 채택됐다(PLAN-archive).
  - 블록 놓기 키트가 Woodoku, blockblast, Block Game을 읽었다.
- **이미 본 한계:**
  - 비슷한 생김새는 혼동한다. 2048의 256과 128을 혼동했다(STATUS §3).
  - 꿈의 집 판독의 28%가 같은 판독에 닿지 못한다.
- **키트가 쓰러지는 곳은 칸이 규칙적이지 않을 때다.** 그런 곳은 모델 판독(L2)이 맡는다. 모델은 생김새를 가리지 않지만 대가가 있다.
  - 판독마다 질문 1, 3~7초(복잡한 판은 30초)가 든다.
  - 3D 배치에서는 정확도가 떨어진다.
  - 상태를 읽기 쉽게 추상화할수록 규칙이 확인할 것이 준다.

| 하위 종류 | 화면 배치 | 코드 판독(L3) | 비고 |
|---|---|---|---|
| 화살표 빼내기(2D) | 격자, 칸마다 화살표 | 가능: 방향은 견본 4종 | 꺾인 선은 칸 사이 연결을 읽어야 해 더 어려움 |
| 블록 빼내기 | 격자, 블록이 여러 칸 | 가능: 같은 색 이웃 칸을 묶음 | 문 위치·색은 가장자리에서 따로 |
| 물·구슬·색 정렬 | 그릇 자리와 칸이 일정 | 가능: 그릇마다 한 줄 격자 | 가려진 층 `?`는 견본 하나 |
| 실·로프·꼬치 정렬 | 그릇 모양 불규칙, 겹침 | 어려움 | L2 위주 |
| 트리플 타일 | 겹친 더미 + 받침 | 받침만 | 더미의 "맨 위인가"는 모델 |
| 마작 솔리테어 | 층으로 겹침 | 어려움 | L2 |
| 주차·버스 잼 | 비스듬한 3D, 칸에 안 맞음 | 안 됨 | L2만, 또는 직접 두기 |
| 3D 큐브·나사 | 3D | 안 됨 | 제외 |

**그래서 범위를 기하로 자르기를 권한다.**

| 묶음 | 하위 종류 | 덮는 게임 |
|---|---|---|
| 코드 판독까지 가는 것 | 화살표 2D, 블록 빼내기, 물·구슬·색 정렬 | 약 12개 |
| 모델 판독으로만 두는 것 | 실·로프·꼬치 정렬, 트리플 타일, 마작 | 약 8개. 직접 두기보다 나은지 재 보고 정함 |
| 계열에서 뺄 것 | 주차·버스 잼(3D), 3D 큐브, 나사 | 직접 두기 |

계열은 "빼내기"와 "정렬" 둘로 두고, 각 계열이 약속하는 범위를 2D의 규칙적인 배치로 좁힌다.

### 5.5 제안한 순서 (결정 전)

1. **판독부터 싸게 재기**(계열 코드를 쓰기 전)
   - 빼내기·정렬의 기술자와 상태 형식(JSON 스키마)만 정한다.
   - 하위 종류마다 게임 2~3개의 레벨 화면을 몇 장씩 찍는다.
   - 모델이 그 화면을 상태 형식으로 읽게 해서 정답과 맞춘다. `eval offline`이 보관된 화면으로 모델을 재는 도구라 이 틀에 붙일 수 있다.
   - 같은 화면에서 격자 키트가 칸을 나누고 묶는지도 본다.
   - 이것으로 하위 종류마다 모델 판독 정확도와 키트가 서는지가 나온다.
2. **빼내기 계열:** 규칙 모델, 풀이기, 기술자를 쓰고 L2로 한 번 끝까지 돌린다. 게임 2~3개를 한 판씩 두고, **같은 게임을 직접 두기로 둔 것과 견준다**.
3. 판독이 막는 것이 보이면 키트(L3)를 만든다. 격자 키트에 방향 견본을 더한다.
4. 같은 순서로 정렬을 진행한다.
5. 타일 짝 맞추기는 ①②의 결과를 보고 정한다. 머지는 작업·루틴으로 둔다.

**원칙:**
- 계열마다 처음부터 게임 2~3개로 잰다. 한 게임에 맞추는 수정으로 흐르지 않게 하고, 변형 값으로 안 되는 게임은 고치지 않고 제외한다.
- 이 순서면 200위 안의 등록 계열 게임이 9개에서 약 30개(빼내기 12, 정렬 8~10)로 는다.
