# 단계 4 실측: 생성 어댑터로 실사이트 2048

작성: 2026-11-13. 커밋 `d54e69f`. 사용자 승인 범위: `march2048_4x4` 1판, `doge2048` 1판, 둘 다 `--generate`.

**이 실측이 재는 것:** 프로필과 손으로 쓴 reader 없이, 모델이 쓴 어댑터로 실사이트를 끝까지 두는지.
`march2048_4x4`는 [웹 실측 1차](2026-11-13-web-baseline.md)와 같은 조건이라 직접 비교된다. `doge2048`은 타일이 숫자가 아니라 그림인 처음 보는 사이트다.

## 실행

```sh
python -m gamelab.eval web --site march2048_4x4 --generate --adapter-store out/web/step4-adapters --objective reach_value --target 2048 --compute 500 --max-seconds 3000 --vision-model gpt-6.1-sol --out out/web/step4-march2048_4x4
python -m gamelab.eval web --site doge2048 --generate --adapter-store out/web/step4-adapters --objective reach_value --target 2048 --compute 500 --max-seconds 3000 --vision-model gpt-6.1-sol --out out/web/step4-doge2048
```

풀이기는 2048 전용 expectimax, 예산 500. 브라우저는 Playwright Chromium(headless), 1280×1000.

### `march2048_4x4`

- 생성 어댑터(120줄)가 채택 시험의 전이 6/6을 통과했다. 플레이 중에는 다시 배우기 없이 1,051수를 모두 확인했고 오독은 0이다.
- 판 읽기는 1차와 같은 품질로 됐다. 한 수 시간도 같다.
- 2048에 못 간 것은 판독 문제가 아니다. 오독이 0이므로 풀이기와 새 타일 운 탓이다. 1판씩이라 1차와의 성적 차이는 말할 수 없다.
- 시작 비용은 1차(질문 1번)보다 크다. 같은 사이트의 다음 판은 저장 어댑터(`out/web/step4-adapters/march2048-site.pages.dev-743b1657/`)를 다시 쓰므로 이 비용이 없다. 재사용은 이번에 돌리지 않았다.

### `doge2048`

- 처음 4개 화면은 모델이 판(4×4, 상자 `[404,294,473,473]`)과 값을 읽었다.
- 5번째 화면부터는 `screen: other`였다. 첫 8 타일을 만들자 사이트가 "NEW BRAINROT UNLOCKED" 덮개(새 캐릭터 소개, "tap or swipe to keep merging")를 판 전체에 띄웠다.
- 탐색은 덮개를 닫지 못하므로(PLAN "단계 4의 지금 상태"의 아는 한계) 판을 찾지 못한 채 끝났다. 판을 하나도 두지 않았다.
- 덮개는 새 타일 값을 처음 만들 때마다 나올 것으로 보인다. 그래서 setup 단계로는 막을 수 없고, 탐색과 플레이 중에 덮개를 닫는 경로가 있어야 이 사이트가 된다.

## 하지 않은 것

- 판 수가 각 1판이다.
- 저장 어댑터 재사용, 다시 배우기(처음 보는 값에서 멈춘 화면), `--perturb`, 다른 평가 사이트(`game2048_com`, `march2048_5x5`·`6x6`, `play2048_co_win_in_four`), 기준선 `ovolve_2048`·`play2048_co`에서 생성 대 기준 어댑터 비교.
