# Play 스토어 정적 게임 24개 실측 (2026-11-15)

`docs/reports/2026-11-15-playstore-static-games.md`에서 고른 24개를 에뮬레이터(`army-game`, Android 36, arm64)에 Play 스토어로 설치하고, 범용 에이전트(`eval android`)로 게임마다 한 판씩 돌렸습니다.

## 조건

- 모델은 `gpt-6.1-sol`이고, 판마다 처음부터 시작했습니다(`--regenerate`). 한도는 300수·900초·compute 500입니다. 묶음 하나에 세 판을 넣었고 판은 차례로 돌렸습니다.
- `--hint`에는 게임 이름과 한 판의 끝을 한두 문장으로 주었습니다. 끝이 없는 게임은 "첫 레벨 하나를 깬다", "첫 주문 하나를 채운다"로 끝을 정했습니다(아래 실측 표의 "정한 끝").
- `--accept-consent`(약관 동의를 에이전트가 누를 수 있게 함)를 켰습니다. 첫 묶음에서 이 옵션을 빠뜨려 로얄 매치가 약관 화면에서 바로 포기했으므로, 그 판은 실행 설정 실수로 보고 옵션을 켜서 한 번 다시 돌렸습니다. 첫 묶음의 캔디크러쉬와 Tile Club은 옵션 없이 돌았지만 약관 화면에 막히지 않았습니다.
- 코드는 고치지 않았습니다. 실측을 막는 고장이 없었습니다.
- **한계**: 게임마다 한 판입니다. 같은 게임을 다시 돌리면 결과가 달라질 수 있습니다. 결과는 실행 한 번의 사실이지, 그 게임의 성공률이 아닙니다.
- 결과 파일은 `out/review/ps-*/`(끝 화면 PNG, 판 기록 JSON)와 `out/review/ps-*.log`에 있습니다. `out/`은 추적하지 않습니다.

## 게임별

사실(로그·캡처로 확인)과 추정을 나눠 적었습니다. 추정에는 "(추정)"을 붙였습니다.

- **캔디크러쉬사가**: 지도에서 레벨 3을 누르고 Play로 들어갔습니다. match3로 알아봤지만 판 읽기(`describe_game`)가 맞지 않는다고 답해(`fits:false`, 설탕 장애물이 있는 불규칙한 판) 직접 플레이로 갔고, 13수 만에 장애물 50개를 다 치웠습니다. 수당 약 33초가 걸렸습니다.
- **Tile Club**: 튜토리얼 손가락이 있었지만 그대로 두어 레벨 1을 깼습니다. 수당 약 10초로 가장 빨랐습니다.
- **로얄 매치**: 약관에 동의한 뒤 레벨 1을 정상적으로 두었고 로켓·TNT도 썼습니다. 수당 약 49초여서 15분에 19수만 두었습니다. 레벨은 수 여유가 있었으므로 시간이 더 있었다면 깼을 것입니다(추정).
- **Match Factory!**: 첫 화면이 본 게임(3D 트리플 매치)이 아니라 시간제 미니게임 "Rescue Bob"이었습니다. 9수 동안 타이머가 0:00이 되어 실패 창이 떴고, 모델이 판이 끝났다고 보았습니다. 시간제라 수당 응답 시간이 그대로 실패로 이어졌습니다.
- **블록 블라스트**: 에이전트는 약관 창과 알림 권한 창을 넘겼습니다. 그 뒤 앱이 Hungry Studio 스플래시에서 멈췄고, 판이 끝나고 몇 분 뒤 다시 캡처해도 같은 화면이었습니다. 에이전트 문제가 아니라 이 에뮬레이터에서 앱이 뜨지 않는 것으로 봅니다(추정). 처음 동의 버튼 탭 두 번에는 화면이 반응하지 않았습니다.
- **Woodoku Blast**: block_placement로 알아봤지만 튜토리얼 손가락·반투명 블록이 판 위에서 움직여 판 읽기가 여러 번 "other"로 끝났고, 직접 플레이로 갔습니다. 직접 끌어 놓아 튜토리얼과 첫 레벨을 마쳤습니다. 47수 가운데 11수는 효과가 확인되지 않았습니다.
- **Bus Fever Party!**: 9번 탭해 레벨 1을 깼습니다. 레벨 타이머에는 걸리지 않았습니다.
- **Bolt Out**: 나사 6개를 7번 탭해 빼서 레벨 1을 깼습니다. 끝 창에 "DOUBLE IT"(광고 보상) 버튼이 있었지만 누르지 않았습니다.
- **Meowdoku**: 첫 튜토리얼이 "Double-tap to place the cat on a cell"을 요구했습니다. 에이전트의 입력에는 두 번 탭이 없고, 탭 두 번을 따로 보내면 사이에 모델 응답 시간(수 초)이 끼어 두 번 탭으로 인식되지 않습니다. 탭 39번, 끌기 11번을 해도 판은 바뀌지 않았습니다.
- **Sudoku.com**: 가장 쉬운 퍼즐을 직접 63수로 풀었습니다(앱 기준 06:06). 끝에 뜬 평점 요청 창은 누르지 않았습니다.
- **SoEasy 2248**: slide_merge(2048류)로 알아봤지만 규칙이 달라(이어 합치기) 직접 플레이로 갔습니다. 합치기는 진행됐고 레벨 1 목표 200 가운데 82까지 갔습니다. 끝에 망치 아이템 모드가 켜져 있었습니다(무료 아이템, 결제는 아님).
- **낱말퀴즈**: 첫 레벨(낱말 둘)을 2수 만에 맞혔습니다.
- **Brain Puzzle 3**: 첫 문제가 "주인공 점수를 상대보다 높게"라는 수수께끼였습니다. 모델이 총·가방·점수판 숫자 끌기 등을 시도했지만 풀지 못했습니다. 화면 아래 광고는 "Pangle Test Ads"였습니다(이 기기에서는 시험 광고가 나오는 것으로 추정).
- **틀린그림찾기**: 10곳을 10번 탭으로 실수 없이 찾았습니다.
- **체스닷컴**: 로그인 없이 컴퓨터 상대 대국에 들어갔고(사람과의 온라인 대국은 시작하지 않음), 백으로 22수(탭 53번)까지 두어 기물 +14로 크게 앞섰습니다. 체크메이트 전에 시간 한도에 걸렸습니다. 한 수가 탭 두 번(출발·도착)이라 판이 길어집니다.
- **디즈니 솔리테어**: 가로 화면입니다. 15번 탭으로 첫 레벨을 깼습니다.
- **가십 하버**: 튜토리얼에서 밀가루를 만들었습니다. 그 뒤 같은 물건을 끌어 겹치는 합치기가 화면상 일어나지 않았고, 모델 메모에도 "옆으로 끈 것이 합쳐진 것 같지 않다"고 남았습니다. 주문(빵)을 채우지 못했습니다. 끌기가 짧거나 빨라 앱이 끌어 놓기로 받지 않았을 수 있습니다(추정, 확인하지 않음).

## 장르별 요약

- **매치3**(2판, 애니팡4 제외): 캔디는 깼고 로얄 매치는 판을 바르게 두었지만 시간이 모자랐습니다. 둘 다 등록 계열(match3)이 아니라 직접 플레이로 두었습니다.
- **타일·마작**(2판): Tile Club은 깼습니다. Match Factory!는 첫 레벨이 시간제 미니게임이라 졌습니다.

- **숫자·논리**(3판): 스도쿠는 풀었습니다. 2248은 진행했지만 시간 한도였고, Meowdoku는 두 번 탭에서 막혔습니다.
- **단어·퀴즈**(2판): 낱말퀴즈는 깼고, Brain Puzzle 3의 수수께끼는 풀지 못했습니다.
- **숨은그림**(1판): 틀린그림찾기를 실수 없이 깼습니다.
- **카드·보드**(2판): 솔리테어는 깼고, 체스는 앞섰지만 시간 한도였습니다.
- **머지**(1판): 가십 하버는 첫 합치기에서 막혔습니다.

## 여러 게임에 공통으로 나타난 것 (구조 개선 제안, 고치지 않음)

1. **수당 시간이 시간 한도와 시간제 게임을 가른다.** 시간 한도 5판 가운데 셋(로얄 매치 49초/수, 체스, 2248)은 바르게 두다가 시간이 다 됐습니다. Match Factory!는 레벨 타이머에 졌습니다. 직접 플레이는 수마다 모델에 화면 전체를 보냅니다(판당 입력 4만~26만 토큰). 등록 계열로 넘어가지 못한 판이 모두 이 비용을 냈습니다.
   - 제안: 직접 플레이에서 한 번에 여러 수(예: 체스의 출발·도착, 확실한 탭 몇 개)를 내게 하기
   - 제안: 판 모양이 정해진 게임(체스, 스도쿠)은 H5처럼 호스트가 판을 읽게 하기
2. **등록 계열이 실제 앱에서는 거의 쓰이지 않았다.** match3·block_placement·slide_merge로 알아본 세 판 모두 판 읽기에서 맞지 않아 직접 플레이로 갔습니다. 앱의 실제 판에는 장애물이 있는 불규칙한 판(캔디), 튜토리얼 손가락이 덮은 판(Woodoku), 같은 이름의 다른 규칙(2248)이 있었습니다.
   - 제안: 계열을 "맞는다/안 맞는다"로만 고르지 말고, 장애물 칸·가린 칸을 허용하는 읽기를 두기
   - 제안: 튜토리얼 손가락이 사라질 때까지 기다린 뒤 다시 읽기
3. **입력 종류가 모자라다.** 직접 플레이 입력에 두 번 탭과 길게 누르기가 없습니다(Meowdoku 막힘). 끌기는 150ms짜리 `input swipe` 하나뿐입니다. 가십 하버는 이 끌기를 합치기가 아니라 선택으로 받았습니다. 판이 끝난 뒤 에뮬레이터에서 다시 재현해 확인했습니다(아래 "입력 도구 점검").
   - 제안: `double_tap`, `long_press`, 시간을 정할 수 있는 경로 `drag`를 입력에 더하기(아래 순위 참고)
4. **알아보는 단계의 동의 처리.** 게임을 알아보는 단계의 복구기(`agent.py`의 `identify`에 넘기는 `Recovery(...)`)는 `accept_consent`를 받지 않습니다. 그래서 `--accept-consent`를 켜도 이 단계에서는 동의를 거부하고 포기한 뒤, 직접 플레이 단계에서야 동의합니다(블록 블라스트 로그). 이번에는 결과에 영향이 없었지만 질문이 몇 번 낭비됩니다.
   - 제안: 그 `Recovery`에도 `accept_consent`를 넘기기
5. **앱 시작부의 걸림돌은 대체로 스스로 넘었다.** 약관, 알림 권한, Play Games 창, 튜토리얼, 평점 요청은 에이전트가 넘기거나 누르지 않고 지나갔습니다. 로그인·결제·보상형 광고 버튼("DOUBLE IT" 등)을 누른 판은 없었습니다.
   - 사람이 막아야 했던 것은 설치 단계의 본인 확인(고스톱M)과, 앱이 뜨지 않은 경우(블록 블라스트)였습니다.
6. **에뮬레이터 호환.** 24개 가운데 4개가 "기기 호환 안 됨"으로 설치되지 않았습니다. 실제 기기에서는 다를 수 있습니다(추정).

## 입력 도구 점검 (2026-11-15, 실측 뒤)

실측에서 입력 때문에 막힌 판이 있었으므로, 지금 입력 도구를 웹과 Android로 나눠 정리했습니다. 이어서 게임에 더 필요한 입력을 꼽고, 그 가운데 Android에서 되는 것을 에뮬레이터에서 직접 확인했습니다. 확인은 개발자 옵션의 포인터 위치 표시를 켜고, 명령을 보낸 뒤 캡처를 눈으로 보는 방식으로 했습니다. 확인에 쓴 게임은 Meowdoku, SoEasy 2248(다시 설치함), 가십 하버이고, 그 밖에 Chrome과 Play 스토어 검색창을 썼습니다. 코드는 고치지 않았습니다.

### 지금 있는 입력

모델이 직접 둘 때 고르는 입력(`direct.py`, `play_direct.md`)입니다. 기기가 지원하지 않는 종류는 걸러집니다.

| 입력 | 웹 (Playwright) | Android (adb) |
|---|---|---|
| `tap` | 마우스를 누르고 뗌 | `input tap` |
| `swipe` | 누른 뒤 150ms 동안 16ms마다 옮기고 뗌 | `input swipe … 150` 한 번 |
| `key` | 아무 키 | 기본으로는 막힘. `--keys`를 줄 때만 화살표·Enter·Escape(뒤로)·스페이스가 감 |
| `text` | 글자를 하나씩 누름 | 기본으로는 막힘. `--keys`를 줘도 글자가 키 코드로 바뀌지 않음 |
| `wait`, `done`, `give_up` | 됨 | 됨 |
| 두 번 탭, 길게 누르기, 여러 점을 지나는 끌기, 스크롤, 두 손가락 | 없음 | 없음 |

기기 쪽 기능은 계열 코드만 씁니다(`surface.py`).
- **웹**: `HOLD`(누르기, 옮기기, 떼기를 따로 하며 그 사이에 화면을 봄)가 있어, 블록 놓기 계열의 보정 끌기(`carry.py`)가 이것을 씁니다. 화면 요소 읽기(`reads_dom`)도 있습니다.
- **Android**: `TAP`과 `DRAG`뿐입니다. 200ms보다 긴 탭은 제자리 swipe(길게 누르기)로 보내지만, 직접 플레이의 탭은 시간이 고정이라 모델이 고를 수 없습니다.

이번 Android 실측에서 모델이 실제로 쓸 수 있었던 입력은 탭, 150ms 끌기, 기다림 셋입니다.

### 에뮬레이터에서 확인한 것 (Android 16, API 36)

`input`의 사용법 출력에는 `tap`, `swipe`, `draganddrop`, `motionevent DOWN|UP|MOVE|CANCEL`, `scroll`, `keyevent --longpress|--doubletap|--duration`, `keycombination`, `text`가 있습니다. 소스는 touchscreen, mouse, gamepad 등입니다.

명령 하나의 시간(기기 안 셸에서 잼)은 다음과 같습니다.
- `input tap`: 49ms
- `motionevent DOWN`: 82ms, `motionevent UP`: 40ms
- 한 셸 안에서 이은 두 번째 `input tap`: 14ms
- 호스트에서 보낸 `adb emu event send` 한 번: 27ms

| 입력 | 보낸 것 | 결과 (캡처로 확인) |
|---|---|---|
| **두 번 탭** | 한 셸에서 `input tap; sleep 0.12; input tap` | **됨.** Meowdoku 튜토리얼("Double-tap to place the cat")에서 고양이가 놓이고 "Well done!"이 떴습니다. |
| 두 번 탭(간격 없음) | 한 셸에서 `input tap; input tap` | **안 됨.** 칸에 X만 생겼습니다(한 번 탭으로 처리됨). 두 탭 사이에 수십~수백 ms 간격이 있어야 합니다. |
| **여러 점을 지나는 끌기** | `motionevent DOWN`, `MOVE` 여러 번, `UP` | **됨.** SoEasy 2248 튜토리얼에서 두 칸 잇기("GOOD!"), 세 칸 잇기("EXCELLENT!"), V자로 꺾인 세 칸 잇기를 모두 통과했습니다. 실제 판에서는 L자로 4 넷을 이어 16 하나를 만들었습니다(진행 0 → 4/200). 직선 swipe로는 꺾인 경로를 낼 수 없습니다. 명령 7개에 438ms가 걸렸습니다. |
| 합치기 끌기: `input swipe` 150ms | 가십 하버, 같은 물건 둘 | **안 됨.** 끌기가 아니라 선택으로 처리돼 물건 정보 창만 떴습니다. 실측 판에서 막힌 것과 같습니다. |
| 같은 끌기: 300ms | 같음 | **안 됨**(선택) |
| 같은 끌기: `input draganddrop` 기본 시간(455ms) | 같음 | **안 됨**(선택) |
| 같은 끌기: 500ms, 800ms | 같음 | **됨.** 밀가루 둘 → 반죽(Lvl 2) |
| 같은 끌기: `motionevent` 누름 → 200ms 머묾 → 다섯 번 나눠 옮김 → 200ms 머묾 → 뗌 | 반죽 → 거미줄에 덮인 반죽 | **됨.** 빵(Lvl 3)이 되어 실측 판에서 못 한 첫 주문을 그 자리에서 전달했습니다(코인 0 → 2). |
| 영문 글자 | `input text word` (Play 스토어 검색창) | **됨** |
| 한글 글자 | `input text 한글` | **안 됨.** `InputShellCommand.sendText`에서 NullPointerException이 났습니다. 셸 클립보드 명령도 없습니다(`cmd clipboard`: "No shell command implementation."). |
| **두 손가락** (기기 안) | 터치 장치에 `sendevent` | **안 됨.** `/dev/input/event1: Permission denied`가 났습니다. 셸 사용자가 `input` 그룹에 있는데도 막혔으니 SELinux로 봅니다(추정). `adb root`도 "production builds"라 안 됩니다. |
| **두 손가락** (에뮬레이터 콘솔) | `adb emu event send`로 MT 슬롯 두 개 누름·이동·뗌 | **됨.** 포인터 표시가 "P: 2/2"가 됐고, Chrome에서 두 손가락 벌리기로 페이지가 확대됐습니다. 좌표는 0~32767 범위로 바꿔 보내야 합니다. **에뮬레이터에서만 되고 실제 기기에서는 안 됩니다.** |
| 마우스 휠 스크롤 | `input mouse scroll 540 1500 --axis VSCROLL,-15` | **됨.** Chrome 페이지가 아래로 내려갔습니다. 게임 엔진(Unity 등)이 마우스 휠을 받는지는 확인하지 않았습니다. |
| 기울기 센서 | `adb emu sensor set acceleration 2:9.6:0.5` | 값은 설정됐습니다(`get`으로 확인). 게임에서 효과가 나는지는 확인하지 않았습니다. |
| Back 키 | `input keyevent BACK` | 됨(확인 과정에서 창을 닫는 데 씀) |

확인하지 않은 것도 있습니다.
- 게임 안에서의 길게 누르기(제자리 swipe)
- `keyevent --longpress`, `keyevent --doubletap`, `keycombination`
- 입력기 앱(ADBKeyboard 등)을 설치해 한글을 넣는 방법. 외부 APK를 설치해야 해서 하지 않았습니다.

**확인에서 읽은 것**

- 알맞은 끌기 시간은 게임마다 다릅니다. Woodoku는 실측에서 150ms로 블록을 놓았는데, 가십 하버는 500ms부터 받았습니다. 시간을 하나로 고정하면 어느 한쪽이 실패합니다. 끌기 시간을 입력에 넣어 모델이나 호스트가 고르게 하거나, 실패하면 더 길게 다시 보내야 합니다.
- `motionevent`로 웹의 `HOLD`(누르기, 옮기기, 떼기를 따로)와 같은 것을 Android에서도 만들 수 있습니다. 경로 끌기, 누른 채 머무는 끌기, 길게 누르기가 이것 하나로 됩니다. 명령마다 40~80ms가 들어 아주 촘촘한 경로는 느려지지만, 정적 게임에는 문제가 없는 수준입니다.
- 두 번 탭은 한 셸 명령 안에서 간격을 두고 보내면 됩니다. 모델 질문 두 번으로 나눠서는 안 됩니다.

### 제안 순위 (고치지 않음)

1. **입력 하나에 점 여러 개와 시간을 받게 넓히기.** 한 종류로 경로 끌기, 누른 채 머무는 끌기, 길게 누르기, 넘기기가 됩니다. Android는 `motionevent`로 `HOLD`를 더하고, 웹은 이미 있는 `press/move/lift`를 직접 플레이에 연결합니다. 끌기 시간은 실패하면 늘려 다시 보내는 방식이 게임마다 다른 문턱(150ms로 되는 게임, 500ms가 필요한 게임)에 맞습니다.
2. **여러 입력을 한 번에 보내기.** 두 번 탭(간격 120ms)과 체스 같은 두 단계 수를 모델 질문 한 번으로 냅니다.
3. **Android Back 키 기본 허용, 앱 다시 띄우기와 조건까지 기다리기를 루프가 고를 수 있게 하기.**
4. **웹의 오른쪽 클릭·휠, Android 한글 입력**(입력기 앱 설치가 필요해 따로 정함).
5. **두 손가락.** 에뮬레이터 전용으로는 콘솔로 바로 되지만, 실제 기기를 생각하면 기기 안 입력 에이전트(UiAutomation 등)가 필요해 비용이 큽니다. 3D·숨은그림 장르를 다룰 때 다시 봅니다.

## 입력 도구 구현과 다시 잰 세 판 (2026-11-15)

위 "제안 순위"의 1~3번과 웹의 오른쪽 클릭·휠을 구현했습니다. 한글 입력과 두 손가락은 하지 않았습니다.

### 더한 것

- **모델이 직접 둘 때의 입력**(`direct.py`, `play_direct.md`)
  - `drag`: 2~16점 경로. `ms`(100~5000, 기본 600)와 `hold_ms`(0~1500, 기본 150)를 고를 수 있습니다.
  - `double_tap`: 120ms 간격.
  - `long_press`: 400~3000ms, 기본 800ms.
  - `sequence`: 탭·끌기·키 입력 2~4개를 질문 한 번에 보냅니다. 입력 사이는 300ms입니다.
  - `scroll`, `back`, `right_tap`.
  - `relaunch`: 한 판에 2번까지.
  - `wait`의 `until_change`: 최대 15초, 화면이 바뀌면 끝납니다.
  - 프롬프트에 "끌기가 선택만 했으면 더 느리게 다시 보낸다"를 적었습니다.
  - 모델에게는 기기가 지원하는 입력만 알립니다.
- **기기**(`surface.py`)
  - 새 메서드: `stroke`, `taps`, `type`, `scroll`, `back`, `right_tap`, `relaunch`
  - 새 kind: `text`, `scroll`, `back`, `secondary`, `relaunch`
  - 웹(`web.py`)은 `back`을 뺀 전부를 지원합니다.
  - Android(`android.py`)는 `right_tap`을 뺀 전부를 지원하고, `HOLD`(`motionevent`로 누르기·옮기기·떼기)를 더했습니다.
    - `stroke`와 `taps`는 기기 셸 한 줄로 보냅니다.
    - 영문 `text`를 허용했습니다.
    - 이제 블록 놓기 계열의 보정 끌기(`carry.py`)도 Android에서 웹처럼 "집고 → 보고 → 보정해 놓기"로 돕니다. Android 블록 놓기 게임으로는 아직 재 보지 않았습니다.
- **막힌 화면 복구**(`recovery.py`, `recover.md`): `back`.
- **알아보는 단계**: `Recovery`에 `accept_consent`를 넘깁니다(공통 4번).
- **시험**: 411개 통과(전에 403개).
  - 웹: 실제 Chromium에서 경로 끌기, 더블클릭, 오른쪽 클릭, 글자, 휠, 새로고침
  - Android: 가짜 adb에서 보내는 명령
  - 직접 플레이: 새 입력의 검사·좌표 변환·전송, `relaunch` 횟수 제한, 바뀔 때까지 기다리기

### 에뮬레이터에서 기기 메서드를 직접 호출한 결과

- `AndroidSurface.stroke`: SoEasy 2248에서 꺾인 네 점 경로가 0.95초에 4 넷을 16으로 만들었습니다(진행 4 → 8/200).

## 블록 블라스트 다시 시도 (2026-11-15, 입력 도구 구현 뒤)

- 다시 설치하고, 같은 hint로 한 판 돌렸습니다. 결과는 **막힘**이었습니다(포기, 152초, 8수 가운데 확인 1수, 입력 58,720 토큰).
  - 에이전트는 약관 창과 알림 권한 창을 넘겼습니다.
  - 그 뒤 스플래시에서 새 입력을 모두 써 보고 포기했습니다. 쓴 입력은 `wait`의 `until_change`(최대 15초), 탭, `relaunch`, `back`입니다.
- **원인(로그로 확인)**: 앱의 그래픽 스레드가 시작하자마자 `FATAL EXCEPTION: GLThread … IllegalArgumentException: No config chosen`으로 죽습니다.
  - 이 에뮬레이터의 소프트웨어 렌더러(`hw.gpu.mode = lavapipe`)가 cocos2d가 요구하는 EGL 설정을 내주지 못한 것입니다.
  - 프로세스는 살아 있어 스플래시가 계속 보입니다. 다시 띄워도 같습니다. 에이전트가 아니라 실행 환경의 문제입니다.
- **사고**: 원인을 피하려고 에뮬레이터를 `-gpu host`로 다시 켰습니다.
  - 그러자 AVD에 남아 있던 2026-11-13의 `default_boot` 스냅샷(GPU host로 찍힌 것)이 로드됐습니다.
  - userdata가 그 시점으로 되돌아가, 시험용 Google 계정 로그인과 그 뒤 설치한 앱이 모두 사라졌습니다(`dumpsys account`: Accounts 0, 서드파티 앱 0개).
  - 평소 설정(lavapipe)에서는 GPU가 맞지 않아 스냅샷을 읽지 못하고 콜드 부팅했기 때문에, 그동안은 디스크가 유지됐던 것입니다.
  - 블록 블라스트가 GPU host에서 뜨는지는 확인하지 못했습니다. 앱이 이미 사라졌기 때문입니다.

### 블록 블라스트 원인 확인 (2026-11-15, 사용자가 다시 로그인한 뒤)

- **준비**: 에뮬레이터 저장소(`userdata-qemu.img.qcow2` 등)를 APFS 복제로 백업했습니다(`~/.android/avd/army-game-backup-20261115/`). 시험은 모두 `-no-snapshot-load`로 켜서 스냅샷을 읽지 않게 했습니다. 그 결과 GPU 방식을 바꿔도 계정 1개와 앱 8개가 그대로 남았습니다.
- **GPU 방식별 결과**: 셋 모두 앱을 띄우고 1초쯤 뒤에 `GLThread: IllegalArgumentException: No config chosen`이 났습니다(logcat으로 확인).

  | 방식 | 에뮬레이터가 고른 렌더러 | 결과 |
  |---|---|---|
  | 기본 | lavapipe / swangle | 같은 오류 |
  | `-gpu swiftshader_indirect` | swiftshader / swangle | 같은 오류 |
  | `-gpu host` | host / host | 같은 오류 |
  | `-gpu guest` | 지원 안 됨, lavapipe로 대체 | 같은 오류 |

- **해석**
  - 확인한 것: 오류는 `GLSurfaceView$BaseConfigChooser.chooseConfig`에서 납니다. 앱이 요구한 조건에 맞는 EGL 설정이 없다는 뜻입니다.
  - 추정: 호스트 렌더러와 상관없이 에뮬레이터의 EGL 계층(`ro.hardware.egl = emulation`)이 내주는 설정 목록에 앱이 원하는 조합이 없는 것으로 봅니다. 앱이 요구하는 정확한 조합은 확인하지 못했습니다. 게임 코드가 보안 모듈(`libnesec.so`)로 보호돼 있어, APK 안의 dex 14개 어디에도 설정 선택 호출이 없습니다.
- **결론**: 이 에뮬레이터에서는 블록 블라스트가 그리기를 시작하지 못하므로 실측할 수 없습니다. 에이전트나 입력의 문제가 아닙니다. 재려면 실제 기기가 필요합니다. 같은 장르는 Woodoku Blast로 재었습니다(목표 달성).
- 에뮬레이터는 기본 설정(`-no-snapshot-load`)으로 되돌려 데이터를 확인한 뒤 껐습니다.
