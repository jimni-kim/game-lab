# game-lab 구조

> 웹·Android 게임을 **화면만 보고** 두는 범용 게임 에이전트. 사용자가 말로 맡긴 범위(한 판, 레벨 N개, 이어받기, 이름 붙인 작업)를 끝내고 결과를 돌려준다.
> 기준: main (2026-11-24, §36 E0~M11b까지. `m11b-weighty-moves` `f76dd36`을 합친 것). 구조가 바뀌면 이 문서도 함께 고친다.
> 실측 숫자와 남은 일은 [STATUS.md](STATUS.md), 계획과 세션 기록은 [PLAN.md](PLAN.md).

## 1. 전체 구조 (요청 → 실행 → 중단)

```text
 사용자 요청   예) "꿈의 집 하던 판 이어서 레벨 3개 깨줘, 지면 멈춰"
      │
      ▼
┌─ ① 입구 ──────────────────────────────────────────────────────────────
│   데모 대화창  POST /say            eval/serve.py, serve.html
│   CLI         eval web | android --ask "…"
│
│   talk.sort (경량 모델 질문 1번) ─┬─ 게임 요청 ──────────────▶ ②
│                                   ├─ 질문 ("어디까지 했어?") ─▶ 코드가 센 진행 + 마지막 화면으로 답 (판은 안 멈춤)
│                                   └─ "멈춰" ──────────────────▶ cancel 신호 ─▶ ⑧ 중단
└──────────────────────────────────────────────────────────────────────
      │
      ▼
┌─ ② 요청 해석 ─────────────────────────────────────────────────────────
│   request.understand (모델 질문 1번, 답은 호스트가 검사)
│     ├─ 어디서   url (요청 글에 있는 주소만) | app (설치된 앱 목록 가운데서만)
│     ├─ 무엇을   GoalSpec: 목표(끝까지 / 점수·칸 / 수 N개 / 레벨 N개)
│     │                    범위(이어받기 / 새 게임), 멈춤 조건, 허락한 판 밖 행동, 선택지 방침
│     ├─ 작업     task (일일 보상 같은 판 밖 일), wait
│     └─ 힌트     hint (게임에 대한 말 → 식별에 넘김)
│   eval/guard.py     주소가 공개 IP로만 풀릴 때만 열고, 이후 모든 연결을 프록시로 다시 확인
│   eval/emulator.py  앱 요청이면 에뮬레이터(AVD game-lab2)가 켜져 있는지 보고 없으면 켬
└──────────────────────────────────────────────────────────────────────
      │
      ▼
┌─ ③ 화면 연결 (Surface) ───────────────────────────────────────────────
│   surface.py  공통 인터페이스: capture · tap · drag · stroke · key · type · scroll · back
│     ├─ environments/web.py      Playwright Chromium (+ 페이지 요소 outline)
│     └─ environments/android.py  adb (screencap, input tap/swipe/keyevent)
│   frames.py · motion.py  프레임 안정화, 움직이는 부분(튜토리얼 손, 깜빡이는 버튼) 걸러내기
└──────────────────────────────────────────────────────────────────────
      │
      ▼
┌─ ④ 작업 겹 (work.py) ─────────────────────────────────────────────────
│   요청한 범위를 "판(part)" 단위로 잘라 잇는다
│     ├─ 레벨 N개  레벨마다 한 판. 같은 화면에서 이어 감, 진 레벨은 retry 허락 시 다시
│     ├─ 예산      작업 전체에 하나 (입력 수 · 초 · 입력 토큰) → 앞 판이 쓰고 남은 만큼 다음 판에
│     └─ 공유      루틴 책(routine.Book), 모델의 메모(notes)를 판 사이에 넘김
└──────────────────────────────────────────────────────────────────────
      │  판마다
      ▼
┌─ ⑤ 한 판 시작: 게임 식별과 경로 선택 (agent._begin) ─────────────────
│   보관소(adaptation.Store)에서 이 사이트·게임의 기억을 먼저 꺼냄
│   처음 보는 앱이면 밖 조사(research.outside, 질문 1번: 스토어 설명·위키·아는 것) → 그 답을 아래 모든 질문에
│   식별(adaptation.identify, 모델 질문) → 계열 후보 + 실시간 여부
│   ─▶ 경로 하나를 고른다 (자세한 순서는 §2)
│
│     계열 키트 │ 생성 어댑터 │ 만든 계열 │ 실시간 │ 직접 두기(+스토리형, 카드 싸움, 고르기) │ 작업+루틴
└──────────────────────────────────────────────────────────────────────
      │
      ▼
┌─ ⑥ 한 수 루프 (agent._turn) — 매 수 반복 ─────────────────────────────
│   멈춤 검사 ─▶ 판독 ─▶ 수 고르기 ─▶ 입력 보내기 ─▶ 결과 판독 ─▶ 규칙으로 확인
│   (자세한 흐름은 §3)
└──────────────────────────────────────────────────────────────────────
      │  판으로 못 읽는 화면 (결과·지도·팝업·튜토리얼·로딩)
      ▼
┌─ ⑦ 판 밖 화면 ────────────────────────────────────────────────────────
│   scenes.py    화면 종류에 이름 붙이기, 같은 화면을 맴도는지 감시
│   routine.py   "이 화면이면 이 입력"을 코드가 재생 (모델 질문 0)
│   recovery.py  루틴이 없으면 모델이 입력 하나를 고름 (L0) → 다시 판독으로
│                처음 보는 게임이면 메뉴·지도에서 게임 안 도움말을 열어 읽고 닫음 (look_first, research.json)
│   world.py     요청 사이에 남는 상태 (가진 것, 작업을 다시 할 수 있는 때)
└──────────────────────────────────────────────────────────────────────
      │
      ▼
┌─ ⑧ 종료와 돌려주기 ───────────────────────────────────────────────────
│   한 판의 끝 (Outcome)                     작업의 끝 (work.handback)
│     goal_reached   목표 달성                  끝난 까닭, 깬·진 레벨
│     game_over      게임이 끝남                쓴 것 (입력·수·판 밖 행동·토큰)
│     stopped        사용자 멈춤 조건 충족       멈춘 화면 (다음 요청의 이어받기 지점)
│     budget_exhausted  입력·시간·토큰·cancel   ─▶ told (한 줄 요약)
│     gave_up        더 할 게 없음 / 오류       ─▶ talk.handed_back (대화창 문장, 코드가 만듦)
│     unsupported    계열을 못 씀               ─▶ out/ 에 NAME-NN.json, -final.png, summary.json
│   레벨이 끝날 때마다와 멈춘 화면에서 화면의 숫자를 읽음 (scenes.measures → 부분마다·작업의 measured)
│   직접 두기 질문이 4개 이상이면 복기 (review.py, 질문 1번, 판 예산 밖) → 교훈을 다음 작업에
│   끝날 때 보관: 판독기 값, 루틴, 복구, 만든 계열, 실시간 준비 답, 세계 기억, 조사, 카드 규칙·그림, 교훈
└──────────────────────────────────────────────────────────────────────
```

## 2. 경로 선택 순서 (⑤ 상세)

위에서부터 처음 맞는 경로로 간다. 등록된 계열은 사람이 쓴 코드로 빠르게 두고, 처음 보는 게임은 모델이 직접 맡는다.

```text
 판 시작
  │
  ├─ 작업 요청(task)인가? ── 예 ─▶ [작업+루틴]  계열을 찾지 않음. 세계 기억이 "아직 때가 아님"이면 남은 시간을 돌려주거나 기다림
  │
  ├─ 전에 실시간 게임으로 둔 적 있나? ── 예 ─▶ [실시간]  보관한 준비 답으로 질문 없이 루프 시작
  │
  ├─ 전에 만든 계열이 있나? ── 예, 첫 화면이 규칙에 맞음 ─▶ [만든 계열]  다시 씀
  │
  ├─ 이 사이트에 보관한 판독기가 있나? ── 예 ─▶ [계열 키트 / 생성 어댑터]  식별 질문 0
  │
  ├─ 처음 보는 앱이면 밖 조사 (질문 1번, 등록 계열이 뚜렷하면 family를 받음)
  │
  ├─ 식별 (모델 질문)
  │    ├─ 실시간(떨어지는 블록)이라고 함 ──▶ [실시간]
  │    └─ 계열 후보 있음 ──▶ 후보마다 판이 읽히는지 시험(probe)
  │           ├─ 키트가 있는 계열 ──▶ [계열 키트]
  │           └─ 키트가 없는 계열 ──▶ [생성 어댑터]
  │
  ├─ 후보가 없거나 모두 실패 ─▶ 설명 질문(made.describe): "격자 하나 + 수 한 종류"에 맞나(fits)?
  │    └─ 맞음 ──▶ [만든 계열]  모델이 규칙·풀이 모듈을 코드로 씀
  │
  └─ 그 밖 ─────────────────────▶ [직접 두기]  이야기 화면이면 [스토리형] 겹이 얹힘
                                   내 차례의 카드 전투면 [카드 싸움] 겹 (모델의 fight_turn 표시, 또는 아는 카드 그림이 손패 자리에 보임)
                                   되돌릴 수 없는 선택이면 답의 pick에 후보마다 예상 (보상만 사람에게 물음)

 계열이 판을 놓았을 때 (판독이 "앞 판 + 수"의 결과가 아님 = inconsistent)
  ① 새로 읽은 판에서 다시 시작 (두 판독자가 칸마다 같을 때, agent._reseed)
  ② 그래도 안 되면 직접 두기로 넘겼다가 몇 입력 뒤 계열이 다시 붙음 (agent._give_up)
```

## 3. 한 수 루프 (⑥ 상세)

```text
 ┌──────────────────────────────────────────────────────────────────┐
 │ 0. 멈춤 검사   cancel("멈춰") · 입력 수 · 시간 · 토큰 → 넘으면 ⑧
 │
 │ 1. 판독  — 위 층이 안 되면 아래 층으로
 │     L3  코드 판독기 (계열 키트 / 생성 어댑터)        질문 0, 빠름
 │     L2  모델이 판을 읽고 규칙 모델이 검사              질문 1
 │     L0  판이 안 보임 → ⑦ 판 밖 화면 (루틴 → 복구)
 │
 │ 2. 수 고르기   계열의 풀이기 (solvers/)
 │     · 3매치에서 목표를 코드가 못 재면 상위 6수 가운데 모델이 번호로 고름 (_pick)
 │     · 풀이기가 둘 수 없다 → ⑦ 로 / 판이 제자리 → game_over
 │
 │ 3. 입력 보내기   화면 좌표로 바꿔 Surface 로 (tap · drag · key · swipe)
 │
 │ 4. 결과 판독 + 확인 (규칙 모델이 예상한 결과와 비교)
 │     confirmed     예상대로 → 목표 진행 갱신, 판독기가 새 모습 학습
 │     absent        게임이 수를 안 받음 → 그 수 제외, 계속되면 판독기를 의심
 │     inconsistent  예상과 다름 → 다시 시작(_reseed) 또는 직접 두기로 넘김
 │     terminal      규칙상 게임 끝 → game_over
 └──────────────────────────────────────────────────────────────────┘
        ▲                                                │
        └──────────────────── 다음 수 ───────────────────┘

 직접 두기는 이 루프 대신 모델이 입력을 고름 (확인은 "화면이 바뀌었나"뿐). 카드 싸움 겹은 그 안의 코드 루프:
   판독(read_turn, 질문 1번) → 손패를 생김새로 가름(12×12 그림) → 탐색(순서·대상, 4만 마디) → 카드 끌기 → 턴 끝
   → 손패가 돌아올 때까지 봄 → 다음 판독을 앞 턴의 예상과 맞춰 봄 → 어긋나면 규칙을 본 값으로 고쳐 씀(fit)

 실시간 경로는 이 루프 대신 realtime.py 의 자체 루프 (초당 4~8번 읽기, 모델 없음)
   준비(모델 1번: 우물·조작·시작 입력·다음 조각 상자·층 목표) → 칸 읽기 → 풀이기로 놓을 곳 계획 → 한 틱에 한 걸음 조작 → 쌓인 모양 확인
```

## 4. 모듈별 역할 및 지원 범위

### 4.1 입구와 요청 해석

| 모듈 | 역할 | 지원 범위 |
|---|---|---|
| `eval/serve.py`, `serve.html` | 데모 페이지. 왼쪽 게임 화면(실시간), 오른쪽 대화창. `POST /say`, `/ask`, `/stop`, `GET /ws` | 한 번에 한 판(도는 중의 새 게임 요청은 거절), 판당 입력 6000·900초·입력 토큰 30만, 하루 20판, 대화 하루 200번. `127.0.0.1`에만 열림(바깥은 Cloudflare 터널), 접근 토큰 + Origin 검사 |
| `eval/talk.py` | 대화창 문장. 말 가르기(게임 요청/질문/멈춤)와 질문의 답은 모델, 시작 약속과 끝 보고는 **코드가 확인된 값으로** 만듦 | 한글이 있으면 한국어, 아니면 영어. 질문 답은 판과 따로 둔 대화용 모델(토큰도 따로 셈) |
| `request.py` | 자연어 요청 → `GoalSpec` + 주소/앱 + 힌트. 모델 질문 1번, 답은 호스트가 검사 | 목표 4종(`play_until_end`, `reach_value`, `actions`, `levels`), 범위 2종(`current_game` 이어받기, `new_game`), 멈춤 조건(`lost` 또는 사용자 말, 4개까지), 허락한 판 밖 행동 4종(`boosters`, `currency`, `continue`, `retry`, 기본은 없음), 이야기 선택지 방침. 주소는 요청 글에 실제로 있는 것만, 앱은 설치 목록에 있는 것만 받음 |
| `contracts.py` | 루프·계열·어댑터가 함께 쓰는 형태(`GoalSpec`, `Budget`, `Outcome`, `Scope`) | 종료 8종: `goal_reached`, `game_over`, `stopped`, `budget_exhausted`, `user_stopped`, `needs_recovery`, `gave_up`, `unsupported` |
| `eval/guard.py` | 요청으로 연 페이지가 공개 인터넷에만 닿게 함 | 루프백·사설망·CGNAT·링크 로컬 거부. 리다이렉트·하위 프레임·WebSocket까지 프록시가 연결마다 다시 확인(DNS rebinding 방어) |
| `eval/emulator.py` | 데모가 쓰는 Android 에뮬레이터 관리 | 켜져 있으면 그대로 쓰고, 없으면 `game-lab2` AVD를 켬(E6부터). 서버가 켠 것은 서버를 내릴 때 끔. 여러 대면 `--serial` |
| `eval/web.py`, `eval/android.py` | CLI 진입점. 사이트·앱 하나를 N판 돌리고 결과 파일을 남김 | 웹은 `sites.json`의 이름 또는 `--ask` 주소, Android는 `--package` 또는 `--ask`(설치된 앱 가운데서 고름) |

### 4.2 화면

| 모듈 | 역할 | 지원 범위 |
|---|---|---|
| `surface.py` | 화면 공통 인터페이스 | `capture`, `tap`, `taps`, `drag`, `stroke`(몸짓), `key`, `type`, `scroll`, `back`, `right_tap`, `relaunch`, `elements` |
| `environments/web.py` | Playwright Chromium | 페이지 요소를 글로 넘기는 `outline`(직접 두기에서 씀) |
| `environments/android.py` | adb | `screencap`, `input tap/swipe/keyevent`. 에뮬레이터 찍기 약 97~331ms |
| `frames.py`, `motion.py` | 프레임 안정화, 움직이는 것 걸러내기 | 튜토리얼 손·깜빡이는 버튼을 모델에게 보이는 그림과 "바뀐 곳"에서 뺌 |
| `carry.py` | 끌어 옮기기 조준 | 잡은 조각이 손가락 위에 크게 그려지는 게임에서, 그려진 위치로 조준하고 최소 누름 시간을 잼 |

### 4.3 작업과 한 판

| 모듈 | 역할 | 지원 범위 |
|---|---|---|
| `work.py` | 요청 범위만큼 판을 잇고 결과를 돌려줌(`handback`, `told`) | 레벨 N개 연속(같은 화면, 재시작 없음), 작업 전체 예산을 판마다 나눔, 진 레벨은 `retry` 허락 시 다시. 하트 0이면 다음 하트까지 남은 시간을 돌려줌. 레벨이 끝날 때와 멈춘 화면에서 화면의 숫자(`measures`)를 읽어 남김. "N층까지"(`until_level`의 층·스테이지·날) |
| `agent.py` | 한 판의 루프: 경로 고르기 → 판독 → 수 → 확인 → 종료 | §2·§3의 흐름 전체. 진행은 `agent.progress`로 대화창에 알림 |
| `adaptation.py` | 게임 식별(`identify`), 계열 판독기 보정·채택 검사, 보관소(`Store`) | 사이트(앱)마다, 한 앱에 게임이 여럿이면 게임마다 폴더 하나: 판독기 값, 복구, 루틴, 메모(`memory.json`: 규칙·길·안 된 것·판의 상태 `run`과 읽은 글 `known`, 카드 싸움의 `card_rules`·`card_looks`·`card_places`, 복기의 `lessons`·`reviews`), 계열 없음(`unfamiliar.json`), 조사(`research.json`), 만든 계열(`made.json`), 실시간 준비 답(`falling.json`), 세계 기억(`world.json`) |
| `research.py` | 두기 전의 조사. 밖(스토어 설명 `hl=en`, Wikipedia 첫 글, 모델이 아는 것)을 질문 하나로 `controls`·`rules`·`win`·`avoid`·`terms`로. 게임 안 도움말은 복구·직접 두기 질문의 `look_first`로 | 처음 보는 앱만, 식별 앞에서 한 번. 토큰 6만까지 판 예산 밖. eval·데모는 켬(`--no-research`) |
| `review.py` | 작업이 끝난 뒤의 복기(`review_work`): 작업의 기록과 마지막 화면으로 교훈을 다시 씀 | 직접 두기 질문이 4개 이상인 작업만(오류·취소는 뺌). 교훈 8개, 토큰 2만까지 판 예산 밖. eval은 켬(`--no-review`), 데모는 끔 |

### 4.4 경로 (게임을 두는 방법)

| 경로 | 모듈 | 하는 일 | 지원 범위 |
|---|---|---|---|
| 계열 키트 | `kits/`, `adapters/kit.py` | 모델이 첫 화면을 보정해 주면 그 뒤로는 코드가 판을 읽고 풀이기가 수를 고름 | 블록 놓기, 2048, 지뢰찾기, 3매치, 소코반(이길 수 없는 판이면 `retry` 허락 시 레벨 다시 시작). 라이브 예산 바닥 값(2048 8000, 지뢰찾기 20000, 블록 놓기 1000) |
| 생성 어댑터 | `adapters/generated.py`, `sandbox/` | 모델이 판독 코드를 쓰고, 격리 실행기에서 기록한 화면 전부로 채택 시험 | 키트가 없는 등록 계열(지금은 클론다이크) |
| 만든 계열 | `made.py` | 등록 안 된 게임을 모델이 설명하고 규칙·풀이 모듈을 코드로 씀(격리 실행). 보관해 다음 판에 다시 씀 | 격자 하나 + 수 한 종류(칸 누르기, 방향키, 칸에서 칸으로 끌기, 고르고 완성하기)에 맞는 게임. 예: 스도쿠 |
| 직접 두기 | `direct.py`, `lattice.py` | 계열이 없으면 모델이 입력을 고름. 한 번에 12수까지 묶어 보냄. 턴을 넘긴 뒤에는 화면이 쉴 때까지 코드가 기다림. 그림뿐인 화면의 격자 판은 모델이 자리를 한 번 말하면 코드가 칸을 생김새로 묶어 글자 판으로 주고, 모델은 칸을 행·열로 누름(이때 묶음은 24수까지) | 어떤 게임이든. 확인은 "화면이 바뀌었나"뿐. 예: 워터 소트, 워들, 마작, Singles |
| 카드 싸움 | `fight.py`, `read_turn.md` | 직접 두기 안의 겹. 내 차례의 카드 전투를 판독 질문 하나로 읽고, 코드가 손패의 순서·대상을 탐색해 카드를 끌어 내고 턴을 끝냄. 카드의 열쇠는 그림(이름은 곁에만), 규칙은 가설이라 본 값으로 고쳐 쓰고, 규칙 없는 카드는 남는 에너지로 써 보고 배움 | 피해·방어·뽑기·에너지·"앞서 낸 카드마다"로 셀 수 있는 카드. 조건·상태 카드(`other`)는 셈하지 않음. 탐색은 한 턴만. 예: Rogue Adventure |
| 고르기 | `direct._pick`, `agent._after_pick` | 되돌릴 수 없는 선택(보상·지도의 길·상인·이벤트)에서 집는 답에 후보마다 예상(`foresee`)과 까닭. 결과의 `adaptation.picks`와 복기에 남김 | 질문을 더하지 않음. 보상만 지켜보는 사람에게 45초까지 물음(`agent.PICKS_ASKED`), 답이 없으면 모델의 고름 |
| 스토리형 | `direct.py` 위의 겹 | 대사 줄은 코드가 넘기고, 선택지는 모델이 봄 | 되돌릴 수 없는 선택은 방침(`--choices`)이 있을 때만 누르고, 없으면 그 자리에서 돌려줌 |
| 실시간 | `realtime.py` | 떨어지는 블록류. 모델은 처음 한 번만, 그 뒤는 코드가 초당 4~8번 읽고 조작 | 키 조작(웹)과 누름·쓸기(Android), 다음 조각 미리보기, 층의 목표, 4칸이 아닌 조각(1~5칸) |
| 작업+루틴 | `routine.py`, `world.py` | 이름 붙인 작업(나무 모으기, 일일 보상)을 판 밖 화면에서 함 | 모델이 한 번 찾은 길을 코드가 재생, 때가 안 된 작업은 남은 시간을 돌려주거나 기다림 |

### 4.5 계열 (규칙 + 풀이기)

| 계열 | 규칙 모델 `rules/` | 풀이기 `solvers/` | 판독 |
|---|---|---|---|
| 2048 (`slide_merge`) | 미는 방향, 합치기 | expectimax | 키트 |
| 지뢰찾기 (`minesweeper`) | 열기, 깃발 | 확률 + 찍기(두 수 살아남기, 끝판 전부 따지기) | 키트 |
| 블록 놓기 (`block_placement`) | 놓기, 줄 지우기 | 탐색 `search` + 끝 판 값 | 키트 |
| 3매치 (`match3`) | 바꾸기, 터뜨리기, 레벨 목표 | 표본 탐색 `sampled` | 키트 |
| 클론다이크 (`klondike`) | 1장·3장 뽑기 | `hindsight` | 생성 어댑터 |
| 소코반 (`sokoban`) | 한 걸음, 상자 밀기 | 밀기 단위 A* `search`(찾은 길을 기억) | 키트 |
| 떨어지는 블록 (`falling`) | 놓기, 줄 지우기, 층 목표 | `lookahead`(다음 조각 하나) | 실시간 루프 |

계열마다 기술자(`blueprint/families/`)가 판 모양·수 종류·조작·바닥 예산을 적고, `catalog.py`가 등록한다.

### 4.6 판 밖 화면

| 모듈 | 역할 | 지원 범위 |
|---|---|---|
| `scenes.py` | 화면 종류 이름 붙이기, 맴돌기 감시 | 판, 결과, 지도, 팝업, 튜토리얼, 이야기, 다른 퍼즐, 로딩 |
| `routine.py` | 모델이 판 밖 화면에서 보낸 입력을 "이 화면이면 이 입력"으로 보관했다가 코드가 다시 보냄 | 화면 전체와 누른 자리가 같아 보일 때만 재생. 안 먹은 단계는 빼고 모델에게 다시 물음. 로딩은 기다릴 화면으로 보관 |
| `recovery.py` | 판을 못 읽을 때 모델이 입력 하나로 답함(L0) | 끝 화면 판정(이김/짐), 하트 소진, 멈춤 조건 충족(`stop`) 판정도 여기서 나옴 |
| `world.py` | 요청이 바뀌어도 남는 게임 상태 | 가진 것, 작업마다 다시 할 수 있게 되는 때 |

## 5. 하지 않는 것

- **누르지 않음:** 광고, 결제, 로그인, 외부 링크, 게임의 힌트·자동 버튼, 진행 중인 판을 버리는 새 게임. 실제 돈이 드는 것은 허락해도 안 함.
- **허락이 있어야 함:** 부스터, 게임 재화, 이어하기, 진 레벨 다시 하기(공짜로 주고 그것 없이 못 넘어가는 튜토리얼 부스터만 예외).
- **안전 장치 없음:** 승인 단계, 입력 직전 픽셀 재검사, 영수증은 없다. 화면을 믿고 입력을 보내고, 결과만 규칙 모델로 확인한다.
- **게임 초기화 안 함:** 앱 데이터 지우기·재설치·진행 되돌리기를 하지 않고 지금 진행에서 이어서 둔다.

## 6. 알려진 한계 (요약)

- 레벨의 끝을 모델의 말 하나로 판정한다. 결과 화면 없이 지도로 넘어가면 추정(`inferred`)이라 틀릴 수 있다(D2 실측: 깬 레벨을 "짐"으로 셈).
- 만든 계열로 갈지 직접 두기로 갈지가 설명 질문 한 번의 답(`fits`)에 달렸다.
- 계열이 판을 놓는 까닭 가운데 `inconsistent`만 되살린다. 판이 안 보이거나 입력이 안 먹으면 판이 끝난다.
- 3매치는 수당 6~20초가 든다(판독 한 번에 3~7초).
- 카드 싸움에서 코드가 셀 수 있는 규칙이 적어(M11b: 10개 가운데 넷) 에너지를 남기고 턴을 끝낸다. 판독의 절반 가까이가 "턴 아님"이다.
- 조사·복기·선택의 예상이 도왔는지는 재지 못했다(같은 게임을 두 번 처음 열 길이 없음).

자세한 실측 숫자와 남은 일은 [STATUS.md §3](STATUS.md)을 본다.
